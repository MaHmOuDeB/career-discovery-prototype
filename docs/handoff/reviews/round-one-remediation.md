# First review remediation

The pre-review source snapshot and first report are alongside this file. Current source is in the project directory in SCOPE.md. The main session applied the following changes.

| Finding | Change | Acceptance evidence |
| --- | --- | --- |
| 1. Mandatory language lost | Separate a comma-introduced preference from the minimum, and recognise explicit candidate conditions under Additional Information. Benefits still have their own section. | B1 is excluded and B2 is eligible for both reproductions. An isolated benefits clause has no effect. |
| 2. Scoped experience | Parse scope after the experience noun as well as before it. Use exact scoped months and keep a generic bucket for generic requirements. Carry shared tenure across explicitly named catalogue tools. | SQL in either position conflicts at zero months and stays unknown when unstated. Conjunctions, alternatives, and a separate general requirement are covered. |
| 3. Evidence attribution | Withhold task credit for relative clauses about other actors and hypothetical or assigned-only actions. Preserve qualified evidence statements that assert personal work. | Tests distinguish team actions and a considered experiment from personal work, including shared participation. |
| 4. Verification and manual state | Require recent feed membership and exact URL plus a matching page heading and visible application action. Treat the previous URL-only proof as unverified when loaded. Skip unsupported targets and current manual opens, and preserve explicit closures through unchanged board refreshes. | Tests cover generic 200 pages, stale membership, wrong URL, legacy records, queue caps, manual opens and feed reappearance. |
| 5. Duties and repeated tasks | Split independent recognised coordinated duties into the same scoring units as separate bullets. Strong fit requires distinct direct capability tags. Repeated evidence for one capability holds the role for scope review. | Combined and separate bullets produce the same rank and task review result. Repeated analysis duties do not earn strong fit. |
| 6. Manual resolution and seniority | Exact reviewed clauses can resolve uncertain requirements. For early-career profiles, senior role signals create a review finding, which can be resolved on a vacancy-specific basis after confirming scope. | Both ranking modes hold the initial case and release it after the relevant reviewed facts are recorded. |
| 7. Pilot diagnostics | Pool top five review-first entries from both methods. Distinguish blank ratings from negative outcomes, report lane-specific label coverage, and calculate missed positives when the frozen corpus is relevance-labelled. | A baseline-only review case enters the blind pack with empty actionable lists. Blank ratings produce undefined rates and a labelled positive omitted from the task lane is counted as missed. |
